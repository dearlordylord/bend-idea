### Официальные инструменты Bend тоже надо отслеживать

[2.0.38, 20 октября](https://github.com/bendlang/bend/releases/tag/v2.0.38) содержит исправления LSP scope через forall, formatter column ownership и bend-lint new buffers/cancellation. [2.0.39, 23 октября](https://github.com/bendlang/bend/releases/tag/v2.0.39) исправляет колонки formatter после `(`, `;`, tuple commas и nested lambdas, а также разделение generic `>` и `=`. [2.0.40, 6 ноября](https://github.com/bendlang/bend/releases/tag/v2.0.40) добавляет внешний proof cache `tools/bend-cache`, сохраняет raw apostrophe literals в formatter и улучшает реальные compiler diagnostics. Отслеживать только старые community repositories уже недостаточно.

## Что переносить к нам

1. **Первый следующий продуктовый срез — optional bend-lint integration, обновив дизайн #89.** Live diagnostics должны учитывать unsaved текущий файл и зависимости, entry roots, distinct compiler/lint outputs, `skipped` coverage и версии JSON/API. Использовать отдельный adapter/process boundary и native inspections/actions, сохранив Scala 3 и общие snapshot/loading owners (A1–A7). [README 0.3.0](https://github.com/MattCozendey/bend-lint/blob/c6f31c0c2ef4587368dd6a5443a6d42e22e975fc/README.md) задаёт реальные новые входы `--overlays`/`entries` и ограничения. Начать с диагностики; автоматическая установка и edits требуют собственной проверяемой реализации. Manifest требует Bun 1.4.4, хотя README ещё говорит 1.4.3: при выборе pairing проверить реальный пакет, не угадывать.
2. **Обновление advanced helper до 2.0.40 — отдельный кандидат.** У нас 0.1.26 уже понимает 2.0.40 CLI reliance reports; полноценные optional semantic operations/recovery остаются привязаны к 2.0.37. Rust main показал, что private recovery требует новых anchors/runtime identities. Это не повод включать новые версии одним whitelist: нужны source-hash pairing, real compiler tests, provenance/notices и fallback (A5–A7). [Текущее собственное состояние](../docs/compiler/support.md).
3. **Перенести идеи регрессионных сценариев независимо написанными fixtures.** Annotated lambdas, nested case recovery, forall scope; completion посреди имени с хвостом; value и constructor с одним spelling; CRLF/Unicode diagnostics; закрытие одного из нескольких views unsaved файла; formatter pinned columns, `> =`, raw apostrophes. Часть уже покрыта: перед добавлением проверить существующие owners/tests. Сценарии берём из [tree-sitter audit](https://github.com/Soulthym/tree-sitter-bend2/blob/997ec087147eb996731cc542ab4931b97049d2a1/docs/upgrades/bend-2.0.36.md), [Rust semantic contract](https://github.com/IlyaGulya/bend2-lsp-rs/blob/1023835018690372c8849d43dfb493d63f8af26f/docs/semantic-api.md) и официальных formatter fixes; acceptance определяется нашим реальным compiler pin и native actions.
4. **Исследовать proof cache отдельным ограниченным экспериментом.** [PR #2045](https://github.com/bendlang/bend/pull/2045) полезен как направление ускорения. Простые file/import hashes недостаточны: root-specific law fills, loading order, compiler identity, dependency reads и reliance входят в корректность. Не переносить upstream timings как наши результаты и не вводить persistent semantic cache без собственной модели инвалидации/измерений (A3, A5–A8).

Не стоит переносить целиком LSP/tree-sitter, Flow syntax, Rust dense storage или heuristic resource warnings. [Entry-scoped extraction API](https://github.com/IlyaGulya/bend2-lsp-rs/blob/1023835018690372c8849d43dfb493d63f8af26f/docs/semantic-api.md) полезен для проверки наших identity/root contracts, но не требует второго resolver. У нас уже есть import cause links, source digests, native inspections, Find Usages batching, explicit value inlays и restricted multi-error recovery (0.1.22–0.1.25); старый вывод 15 октября «#75 ещё полностью blocked» больше не описывает доставленное состояние.

## Ограничения и self-review

Первоисточники — API commits/releases и файлы по immutable revisions. Проверка HEAD относится к default branch, не ко всем незамерженным веткам. Объявленные upstream E2E/benchmarks не запускались здесь. Дополнительная причина иметь собственные acceptance tests для lint integration: upstream [удалил tests и test mode 5 ноября](https://github.com/MattCozendey/bend-lint/commit/f666bde20333a29d43074c40733b9d48953a39e7). Это не доказательство дефекта 0.3.0.

Авторская self-review по REVIEWER.md: изменён только этот исследовательский документ; runtime owners/contracts не менялись. Рекомендации сверены с CHANGELOG, support matrix и A1–A9; edits предполагают native undo, compiler judgments — реальный compiler, completeness/freshness — отдельные состояния. Нового upstream payload/notice obligation нет. Gradle и runtime checks для исследования не запускались. Это не независимый code review и не утверждённый план реализации.
