# bend-lint: architecture and feature opportunities

Assessed 2026-10-07 against [MattCozendey/bend-lint](https://github.com/MattCozendey/bend-lint) at [`c5e950cdcb0024b9ffe66caf730301ed98a99a8d`](https://github.com/MattCozendey/bend-lint/tree/c5e950cdcb0024b9ffe66caf730301ed98a99a8d), the current Bend IDEA implementation, [specification #1](https://github.com/dearlordylord/bend-idea/issues/1), and [ARCHITECTURE.md](../ARCHITECTURE.md). This is research and proposed follow-up work, not a dependency adoption or feature implementation.

Implementation follow-up: the `prototype/bend-lint` worktree now contains an optional native read-only integration; see [setup and limitations](../README.md#experimental-bend-lint-integration-prototype-branch). The research below describes the pre-prototype baseline.

## Recommendation

Take its explicit rule requirements, conservative edit planning, diagnostic identities and compiler-observation experiments as design evidence. Keep our existing source model, snapshot capture, result provenance, formatter and bounded compiler adapters. The most promising new feature is a small set of compiler-backed inspections, starting with a narrowly validated redundant-annotation intention. The most important research lead is its observation of checker demand and usage, but that does **not** provide the supported general resource query missing from our current architecture.

This project targets **Bend 2**, not the older Bend language. Its package requires Bun >=1.2 and loads a Bend source checkout. Our execution of its suite against the current Bend IDEA compiler pin, Bend 2.0.35, passed; details and limits are below. [Package manifest](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/package.json), [compiler loading](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/patch.ts#L148-L163), [our pin](../ci/bend-test-toolchain.properties).

## What it actually implements

The TypeScript library/CLI loads and checks a root, collects requested compiler facts, runs ordered rules, and renders findings or JSON with UTF-16 ranges. Rules expose stable `namespace/name` IDs, optional fact filters and typed-default configuration; an error finding stops later rules. Failed or incomplete checking prevents **all** rules from running, including text-only ones. The result's `ok` does not express the CLI's unsafe/foreign reliance verdict. [Rule contracts](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L20-L107), [checking](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L291-L369), [rule pipeline](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L432-L492), [CLI](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L754-L795).

Only two ready rules ship in `rules/`: trailing whitespace with a declared-safe deletion, and configurable line length with no fix. Spacing/formatting and redundant local annotations are **test examples**, not an established catalog of shipped semantic inspections. Type display, normalization and compiler equality are rule-author helpers, not a complete IDE feature set. [Whitespace rule](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/rules/trailing_whitespace.ts), [line-length rule](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/rules/line_length.bend), [example rules](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/test/lint.test.ts#L341-L375), [helper implementation](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L453-L473).

Bend-authored rules are compiled and run through a separate effects contract; TypeScript rules can execute asynchronous code and receive direct compiler access. These are executable extensions, not passive configuration. Automatic project-rule loading in an IDE would introduce an execution boundary absent from ordinary local inspections. The current CLI requires explicit rule modules. [Bend rule bridge](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L564-L697), [Bend contract](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.bend), [CLI module loading](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L760-L773).

## Feature comparison and priorities

Priorities below are recommendations, not changes to the approved delivery order. Existing implementation evidence matters more than historical scaffold descriptions in overview documents.

| Opportunity | Present evidence in Bend IDEA | Recommended next step |
|---|---|---|
| **P1: compiler-backed redundant-annotation intention** | We already have checked expression-type queries, candidate snapshot validation and an undoable proof intention, but no equivalent shipped annotation inspection was found in the inspected feature owners. | Investigate a narrow Scala inspection/intention using actual compiler equality or validated candidate evidence, source PSI and comments. The upstream example marks removal `suggested`, checks binder type against term type, excludes template instances, and tests preservation of bodies; do not turn a rendered-type comparison into an equivalence proof. Require current-source preconditions, rechecking and undo. |
| **P1: explicit edit applicability and conflict handling** | Formatting already uses an immutable layout edit plan and applies descending edits only while source matches; proof edits already have a validation boundary. | When inspections gain fixes, carry applicability, original source revision, full edit group and refusal reasons as data. Deduplicate exact edits, reject conflicts and apply the entire validated group atomically in one IntelliJ write command. Introduce only the contract needed by the first consumer. |
| **P1 research: measured compiler demand/use** | Explain Bend Resources currently tests up to eight binder substitutions at the first reachable hole. It does not measure general remaining resources; #73 recorded a no-go for the exported compiler API. | Use the instrumented observations as evidence for an upstream observation API proposal, with exact scope and source correlation. Keep #45's broader capability unavailable until that contract and real location-sensitive tests exist. |
| **P2: formatting inspections and project style settings** | Reformat Code already consumes `BendLayoutPolicy`; a formatter and EditorConfig workflow exist. | If users need inline formatting findings, consume the same layout plan rather than add another tokenizer or formatter. A line-length inspection is a plausible small addition, with a clearly defined Unicode/tab width policy and no speculative wrapping fix. Evaluate built-in editor trailing-space behavior before adding a duplicate feature. |
| **P2: filtered semantic observations** | Our structured helper already offers optional first-hole goals, checked expression types, binder comparison and closed-expression normalization. It does not expose a per-term facts stream. | If a new compiler observation capability is implemented, request only required term kinds/definitions/source scope and retain only needed fields. Bound output and memory, mark template instances and unsupported coverage, and key every reply to our existing root/snapshot identity. |
| **P3: configurable rule IDs and CLI findings** | Existing checking diagnostics and formatter workflows solve narrower tasks; there is no general bend-lint-compatible rule execution framework in the inspected implementation. | Stable IDs and native inspection enable/severity settings are useful with the first inspections. A separate lint CLI or external-rule framework needs an actual consumer; avoid adding Bun/Bend rule execution to editor startup or introducing another config file merely for parity. |

## Architecture lessons mapped to existing owners

### Demand-driven compiler facts, without a second semantic owner

The hook receives checked term, expected/inferred type, context, depth, definition, input quantity, returned usage map and source span. Filters select kind, definition, name and file/program scope while facts are collected; each rule then receives only its requested subset, and Base is excluded. Template instances retain a separate marker because several checked instances can share source locations. These are useful requirements for a future observation protocol. [Fact contracts](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L52-L86), [collection and instance mapping](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L298-L356).

Keep protocol decoding and compiler internals in `adapters.structured`; portable, immutable requests/results belong in `analysis.api`/`analysis.model`; presentation belongs in the relevant feature. Features should never receive a live compiler `Book`, term graph or function-valued context. Later consumers include expression-type presentation, inspections and resource explanations, all under A2–A5/A7. Our [analysis key and result model](../src/main/scala/com/dearlordylord/bend/idea/analysis/model/BendCheckResult.scala) already provides provenance; extend it only when the first real operation requires additional fields.

Do not copy bend-lint's rule-order error short circuit into independent IDE inspections. Nor should a compiler failure suppress all local style analysis: the specification requires useful editing on incomplete source. Local PSI inspections and optional checked facts should remain distinct, with unavailable semantic results explicit (A3/A7).

### Resource observations do not resolve #73 by themselves

The project does **not** consume an official exported checker-observation API. Its Bun load hook rewrites `bend.ts` in memory: it renames `term_infer` and `term_check`, replaces them with wrappers that call a new `book.see`, and also changes filesystem/path imports. `comp.ts` receives additional exports for compiled rules. Disk files remain untouched, but the executed compiler module is instrumented source. Exact-match patches, expected function arities and an identity-function self-check detect certain forms of drift; they cannot establish full semantic compatibility. [Patch definitions and wrappers](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/patch.ts#L48-L144), [load hook and self-check](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L699-L751).

This is evidence that useful checker facts can be observed, not evidence that all locations have a supported remaining-resource query. The wrapper reports after a successful term judgment, and normal linting discards rule execution on a failed/incomplete root. An expression's outward usage and input demand do not automatically describe which resources remain before/after sibling composition, branch joins or binder closing. Thus the [#73 investigation](issue-73-compiler-resource-query.md) and [issue criteria](https://github.com/dearlordylord/bend-idea/issues/73) remain relevant: a supported operation must define observation scope, distinguish declaration quantity from demand/use, report unsupported locations, and supply exact source correlation. Candidate substitution verdicts retain their narrower meaning.

Recommended architectural improvement: document these fields and coverage requirements in the eventual upstream protocol proposal, and require an independent capability probe plus real tests for branches, erased/live demand, reusable values, closures and holes. Do not silently replace our pinned helper with load-time compiler patching, change the protected trusted core, or declare the resource gap closed. A production instrumentation design would require a separate reviewed decision under A6–A7 and the trusted-core constraint.

### Fixes need stronger editor preconditions than CLI edits

The upstream pipeline bounds-checks edits and rejects internally overlapping fixes. Its planner merges identical edits, skips conflicts, and applies accepted edits from the end. Applicability is supplied by the rule author: `safe` is not itself a compiler proof. CLI application writes only the linted root and does not recheck the rewritten program in the application path. [Validation](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L473-L491), [planner](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L494-L526), [write path](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L771-L793).

In particular, `applyFixes(file, ...)` filters a fix's edits down to the target file, so a multi-file group can be partially applied. That is unsuitable for an atomic IDE refactoring. Reuse the existing [candidate validation service](../src/main/scala/com/dearlordylord/bend/idea/adapters/intellij/BendProofEditValidatorService.scala) and source revision checks; do not build a feature-local loader or compiler process. Require all edits' preconditions, writable identities and fresh results before an undoable write (A3/A5/A9). The lesson is explicit planning and conflict semantics, with stronger all-or-nothing application in our platform boundary.

### Source mappings and cache lifetimes remain snapshot-owned

Its mapper accounts for compiler-blanked imports using namespace, directory and line content, rejects zero/multiple matches, caches line starts and emits UTF-16 positions. Tests include LF/CRLF, equal-content sources and Unicode JSON ranges. Use these cases to audit our existing mapper rather than create an inspection-specific mapper. An editor additionally needs mappings against unsaved immutable captures and root-relative identity. [Mapper](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L227-L285), [mapping tests](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/test/lint.test.ts#L557-L594), [JSON tests](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/test/lint.test.ts#L1076-L1098), [our mapping tests](../src/test/scala/com/dearlordylord/bend/idea/analysis/model/BendSourceMappingTest.scala).

Its process-wide checked-Base cache is keyed by Base text; loading/checking and subsequent disk source reads are not our immutable editor capture protocol. Do not transfer this cache into an IDE session without proving all compiler, dependency and configuration invalidation inputs. Keep `BendRootSnapshotCapture`, root-owned publication and bounded process isolation (A5–A8). Synchronous compiler calls and cooperative `AbortSignal` checks in this library are not evidence of a killable IDE worker. [Base/check path](https://github.com/MattCozendey/bend-lint/blob/c5e950cdcb0024b9ffe66caf730301ed98a99a8d/src/lint.ts#L298-L346), [our capture](../src/main/scala/com/dearlordylord/bend/idea/adapters/intellij/BendRootSnapshotCapture.scala).
